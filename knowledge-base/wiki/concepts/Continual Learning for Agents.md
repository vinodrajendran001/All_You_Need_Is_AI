# Continual Learning for Agents

## Definition

Continual learning for agents is the controlled updating of an agent after deployment using the stream of trajectories generated by real tasks. Unlike build-time [[Agentic Reinforcement Learning]], production interactions may be unique, arrive asynchronously, contain noisy feedback, and have been generated by an older policy by the time training occurs.

## Why it matters

Deployed agents encounter organization-specific code, tools, user preferences, failure patterns, and changing environments that static training cannot fully anticipate. Learning from those experiences could improve adaptation without waiting for a new general model release. It also converts production traces from passive observability records into potential training data.

## Current synthesis

### The one-rollout problem

GRPO-style build-time RL compares several attempts on the same prompt. Production traffic often yields one attempt per task. [[rLLM - Continual Learning via Real-Time RL for Agents]] replaces the same-task baseline with a cross-task batch mean, so every reward is interpreted relative to the current population of tasks.

This creates useful signal from failures: a zero-reward rollout has negative advantage when the batch mean is positive. On MigrationBench, rLLM reports Qwen3-Coder-30B improving from 43% to 59.2% with batch-normalized single-rollout training.

### Stale trajectories

In an asynchronous system, rollout workers continue acting while the trainer updates. Their trajectories become off-policy. The rLLM source combines PPO clipping with truncated importance sampling to correct policy and engine log-probability mismatches; its no-correction ablation collapses sharply.

### Production safety

Real-time learning must not mean immediately serving every gradient update. A safe architecture separates:

1. trace collection and consent;
2. reward validation and poisoning checks;
3. offline or shadow training;
4. held-out regression and safety gates;
5. staged checkpoint promotion;
6. monitoring, demotion, and rollback.

[[Mahesh Sathiamoorthy - RL Environments Are All You Need]] adds a complementary requirement: maintain replayable environments and held-out tasks so model, prompt, or harness updates can be compared under stable criteria.

## Learning with the weights frozen

Every mechanism on this page so far updates parameters. [[Meta - An Organizational Second Brain]] reports a
deployed agent that improved over three two-week sprints **with no model retraining at all** — the update surface
is 200+ text files, and learning means compiling expert feedback into them under regression tests.

The trade is explicit and worth stating as such. Weight updates can absorb signal no one can articulate; text
updates cannot. In exchange, text updates are **diffable, attributable, revertible, and reviewable by the domain
expert whose judgement is being encoded** — none of which a gradient step offers. For a compliance domain, where
the value being captured is precisely a set of articulable positions, that trade is favourable. For domains whose
expertise is tacit, it may not be.

The loop also answers the question this page leaves open about *which part of an agent should learn*. Meta's
answer is a typed one: procedures are learned as recipes, facts as knowledge files, and the diagnosis step routes
each failure to one or the other by asking **"could the agent have reached the correct conclusion from its source
materials?"** A yes means the procedure is wrong; a no means knowledge is missing; expert disagreement means the
position itself is undecided. That is a more precise localisation than a gradient update, which distributes the
correction everywhere.

The safety architecture this page describes has a direct counterpart: deterministic linting, blind regression
replay where neither agent nor judge knows what changed, and independent adversarial review of the diffs. The
reported "zero regressions" should be read against the fact that the suite is written by the same loop it
validates. See [[Institutional Knowledge Agents]].

## When the update surface is memory, and the writer is a model rather than an expert

The section above records learning with the weights frozen and the update surface made of text.
[[Databricks AI Research - MemCurrent Persistent Memory for Production Agents]] occupies the same
quadrant with one variable changed: **the text is written by a model, offline, from the agent's own
sessions**, rather than compiled from human expert feedback. Their offline consolidation pipeline
extracts implicit learning from new sessions, writes it into mutable **derived memory** files, splits
oversized files, merges duplicates, and resolves conflicts. Raw session traces are retained separately
as append-only **episodic memory**.

That gives this page's open question about **which part of an agent should learn** a third answer
alongside weights and human-curated text: *distilled memory, updated automatically*. And it gives the
**cadence** question a reported comparison rather than a judgement call. On Databricks' internal
benchmark — **114 test cases** drawn from Databricks Genie sessions, scored partly by an LLM judge —
offline consolidation alone reached **63.5%** while the agent's own in-session memory tools alone
reached **53.9%**, with both combined at **66.1%**. The separate memory-type ablation reports derived
memory alone at **66.1%**, episodic traces alone at **35.8%**, both at **68.4%**, against a **22.3%**
no-memory floor.

Read as a continual-learning result rather than a memory one, the implication is specific:
**post-hoc extraction from completed sessions outperformed the agent's judgement during the session**.
This page's existing material already prefers offline or shadow training to immediate online updates,
for safety reasons. The Databricks ablation suggests the offline arrangement may also be the more
*effective* one, at least on this workload — while confirming the cost the page already names, since
the authors note that offline updates arrive with **delay**.

**The safety architecture, however, is where the comparison breaks down.** This page's six-step
production list — collection and consent, reward validation and poisoning checks, offline or shadow
training, held-out regression and safety gates, staged promotion, and monitoring with demotion and
rollback — has close counterparts in the Meta loop above: a deterministic linter, blind regression
replay, independent adversarial review of diffs. MemCurrent's loop as described has **no human review
step and no held-out regression gate on the pipeline's writes**; the adversarial judge and manual
review belong to *benchmark construction*, not to memory promotion. A model that writes its own
durable knowledge files, merges them, and resolves their conflicts with no stated gate is a continual
update path with no demotion mechanism described. The authors do concede that **distillation can drop
details**, with episodic memory recovering some of them — which is a forgetting problem reported
without a measurement of its rate.

Everything here is **first-party**, on one company's benchmark built from one product's sessions, with
the ablations covering memory type and access pattern only. There is no retraining in this loop and no
claim of one; the agent model (Claude Opus 4.6) and memory model (GPT 5.6 sol) stay fixed while the
files change.

## Offline consolidation can update parameters instead of files

[[Ali Behrouz and Vahab Mirrokni - The Sleep Framework]] gives the consolidation schedule a
different update surface from MemCurrent. Wake acquires information in fast memory; sleep
pauses new input, distills into slower parametric memory, and resets temporary high-frequency
parameters. Preallocated low-rank expert blocks provide additional capacity within a fixed
architecture. This is training, not a model rewriting an external Markdown store.

The Google Research blog reports near-zero forgetting for sequential unseen-language
translation and BABILong scaling through **10 million tokens** of consolidation. Neither is
a general no-forgetting guarantee or a native attention-window size. The captured blog does
not establish a production latency budget, full experimental comparability, or independent
replication. Its relevance here is a candidate mechanism and cadence, not demonstrated
continual learning by deployed agents.

## Average transfer can improve while a retained capability regresses

[[Leon Sick et al - On-Policy Self-Training]] supplies a useful counterweight to strong
retention language. Its text post-training uses hand-selected topic descriptors and generated
questions, consistency checks, student-conditioned filtering, and a privileged EMA teacher.
In the all-three-domain mixture, the out-of-domain average rises **0.8 points**, but **MATH-500 falls 4.9 points**;
the MMLU/HellaSwag mixture loses **8.5** there.

The result is not a production-agent trial, but it directly motivates per-capability
regressions in the promotion gate above. Dense self-distillation can improve the aggregate
without preserving every skill. More iterations are not a safety argument either: no-thinking
E2B MMLU peaks at **47.7 after seven rounds** and falls to **46.2 at twelve or twenty**.
A stopping rule without labeled validation remains open.

## Open questions

- How should rewards be normalized across tasks with different difficulty and value?
- How can live feedback be protected against manipulation, privacy leakage, and demographic bias?
- What update cadence balances adaptation against catastrophic forgetting and operational instability?
- Which parts of an agent should learn continually: model weights, prompts, skills, memory policy, or harness code?
- If a model writes, merges, and conflict-resolves its own durable memory, what plays the role of the
  held-out regression gate and the demotion path that this page requires of weight updates?
- Offline consolidation outperformed in-session memory tools **63.5% to 53.9%** on one benchmark. Does
  that ordering survive on workloads where the useful update must take effect before the next turn, not
  the next session?
- Distillation drops details at an unmeasured rate. What would a forgetting metric for a text update
  surface look like, given that no gradient norm or weight delta is available?
- MemCurrent's gains are reported with the agent and memory models held fixed. Nothing establishes
  whether a memory store learned under one model remains useful under another.
