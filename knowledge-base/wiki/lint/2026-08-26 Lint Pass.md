# 2026-08-26 Lint Pass

Full-vault health check run after the Wafer GPU performance-engineering ingest and the
speculative-programmatic-tool-calling / reasoning-trace-privacy ingest brought the tracked
registry to 198 source IDs.

State at the start of the pass: 343 wiki pages, 248 raw source captures, 198 tracked source IDs.

## Headline finding

**Four sources had been summarized but were never cited by any concept, entity, or synthesis
page.** They existed as source summaries and nothing more, so nothing in the wiki graph could
reach the knowledge they carried. Two of them declared an `## Affected pages` list that had
never actually been applied — the summary asserted an integration that did not exist.

This is the first defect class this vault has surfaced that a link checker cannot see: every
wikilink resolved, every frontmatter field was present, and the pages were reachable from the
index. The failure was purely one of *inbound citation* — no downstream page had adopted the
claims. Prior lint passes checked orphans (pages with no inbound links at all) but not the
weaker condition of a source page that only the index links to.

All four are now integrated:

| Source | Integrated into | New section |
| --- | --- | --- |
| ByteByteGo - How ChatGPT Optimizes its Agent Loop | [[Agentic Loop]], [[KV Cache]] | `## The loop is also a caching problem`, `## Prefix stability is an application-level concern` |
| ByteByteGo - Inside Roblox's Bet on World Models | [[World Models]] | `## Engine-authoritative hybrids` |
| ByteByteGo - Three LLM Search Architectures for Delivery Platforms | [[Semantic Recommendation Systems]] | `## Three production answers to the same question` |
| harry0703 - MoneyPrinterTurbo | [[Agent Frameworks]] | `## Integration breadth as its own architecture` |

**New standing check:** after every ingest, verify that each new source ID appears on at least
one non-source page. A source summary that no concept cites is an ingest that did not finish.

## Fixes applied

### Raw-capture traceability (180 source pages, 154 changed)

Source summaries pointed back to their raw captures inconsistently. Three conventions were in
use: a dedicated `## Raw capture` section, an inline `- Raw capture: [[...]]` bullet buried in
`## Citations`, and a dead code-path string such as `` `knowledge-base/raw/sources/...md` `` that
Obsidian cannot follow.

- Added a `## Raw capture` section to **141** summaries that had none, pairing each summary to
  its capture by unique exact `source_url` ↔ raw `source:`/`url:` match after stripping query
  strings and trailing slashes.
- Promoted **13** further inline `- Raw capture:` bullets into proper `## Raw capture` sections.
  These had been skipped by the bulk pass because their `source_url` was empty or did not match
  the raw file's URL exactly.
- Converted **49** dead code-path pointers in `wiki/sources/` into working wikilinks, and removed
  **34** citation lines left redundant by the new section.
- [[Alireza Diri - AI-ML Interviews Collection]] is a composite over 18 separate module captures;
  its `## Raw capture` section now lists all 18 rather than a single link.

Result: **180 of 180** source summaries now open their raw capture in one click, and **0** rely on
a path string.

### Tag canonicalization (27 pages)

Two YAML tag styles coexist in this vault — block sequences and inline flow lists (`tags: [a, b]`).
Every previous tag audit had parsed only the block style, so roughly seventeen pages were
invisible to it. That blind spot is why the following forks survived several lint passes:

| Fork | Canonical | Pages now |
| --- | --- | --- |
| `rl` | `reinforcement-learning` | 22 |
| `agents` | `ai-agents` | 124 |
| `transformer` | `transformers` | 8 |
| `interview` | `interviews` | 6 |
| `ai-security` | `security` | 4 |

Also added missing type-marker tags to **10** pages: 7 concepts lacking `concept`, 2 entities
lacking `entity`, 1 query lacking `query`.

**Correction to the 2026-08-25 report:** that pass flagged all 27 lint reports for using the tag
`lint` instead of `lint-report`. That was wrong. `templates/lint-report.md` specifies
`type: lint-report` with `tags: [lint]`, so `lint` is correct and no change was needed. The rule
going forward is that `knowledge-base/templates/` is the authority for marker tags, not whichever
value happens to be in the majority.

### A validation gotcha worth recording

Traceability checks initially reported three unclaimed raw IDs. The cause was that older source
pages declare a scalar `source_id:` while newer ones use a `source_ids:` list, and the checker
read only the list form. Any future traceability check must scan for `src-` anywhere in the wiki
text rather than parsing one frontmatter field.

## Recorded, deliberately not fixed

The raw store is immutable per `CLAUDE.md`, so its inconsistencies are documented rather than
edited:

- **94** of 248 raw captures have no `source_id` in frontmatter.
- **109** have no `source/raw` tag.
- **106** are not date-prefixed per the `YYYY-MM-DD Author - Title.md` convention.
- `raw/sources/2026-05-08 Kevin Murphy - Reinforcement Learning - An Overview.md` has invalid YAML
  on line 4 — an unquoted colon in `title: Reinforcement Learning: An Overview`. Parsers must
  fall back to a regex read for this file.

Other accepted states:

- **6** summaries have an intentionally empty `source_url`: a PDF working note, a LinkedIn post, a
  community compilation, and newsletters without stable permalinks.
- **39** pages are under 1500 bytes. Most are entity stubs that legitimately need only a
  definition and a link, but this set is the best candidate list for future enrichment.
- `log.md` and the `lint/` reports still contain about 50 code-path pointers. These are
  append-only historical records and were left untouched on purpose; only `wiki/sources/` was
  converted.
- Hub links are not always reciprocal. Making them so would be churn without clear benefit.
