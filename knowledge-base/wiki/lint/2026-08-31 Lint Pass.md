# 2026-08-31 Lint Pass

## Scope

Full pass over 371 wiki pages and 216 raw captures, run immediately after the 2026-08-30 ingest of
nine sources — the largest single batch in the vault's history, which added 19 pages and 9 source IDs
at once. A pass this soon after a large ingest is mostly a check on whether that batch left damage.

It did not. The two defects found were both **pre-existing** and older than the batch.

## Headline finding

A source summary can be orphaned by links that *look* like they point to it.

[[Classic RAG vs Graph RAG vs Agentic RAG]] is a developed 700-word summary that had **zero inbound
links**. Every page that should have linked to it instead linked to the raw capture, using a piped
alias that displayed the summary's own title:

```text
[[2026-05-18 Unknown (LinkedIn post) - Classic RAG vs Graph RAG vs Agentic RAG|Classic RAG vs Graph RAG vs Agentic RAG]]
```

Rendered, this is indistinguishable from a link to the summary. Followed, it lands the reader on the
raw capture and bypasses the curated layer entirely. No previous check could see it: the link
resolves, so the broken-link check passes; the summary exists and is registered, so the ingest checks
pass; and the orphan check had never been run against source summaries specifically.

This is the third instance of the same class of bug the last two passes found — **a check that
validates a link's target but not its intent**. It sits alongside the 2026-08-27 discovery that a raw
capture sharing a filename with a concept page could mask itself from a "summary exists?" probe.

## New check introduced

**Links that bypass a source summary to its raw capture.**

Build the map `raw capture -> summary page that owns it` from each summary's raw-capture link, then
flag any wiki page linking to an owned capture *other than* the owning summary itself. Historical
records (`log.md`, `wiki/lint/`) are excluded, since they legitimately reference captures by name.

Across 216 owned captures the check found exactly 4 violations, all pointing at the one source above.
The vault's linking discipline is otherwise sound, which is why this went unnoticed for three months.

## False positives — checks that need exceptions

Four checks fired on healthy content. Recording them so future passes do not re-litigate.

- **8 unregistered source IDs.** The constituent IDs of
  [[ByteByteGo - System Design and AI at Scale (May 2026 Batch)]] are declared on that composite
  summary rather than in the index registry. This is a **documented decision**, recorded at
  `index.md:486` and `log.md:913`. Any "unregistered ID" check must exempt composite summaries.
- **3 entity pages "missing" a rationale section.** [[Nathan Lambert]], [[Finbarr Timbers]], and
  [[Fei-Fei Li]] were flagged for lacking `## Why it matters`. They all carry
  **`## Why they matter to this vault`**. The check was matching a literal string rather than intent.
- **`Agent Skill` not recording the 288-run null result.** Correct scoping, not an omission: that
  null concerns context *files*, and the page correctly carries the skill-specific findings instead
  (35% skill leakage, generic-beats-personalized, the ~1% listing budget).
- **4 untracked files in `wiki/sources/`.** A WSL/OneDrive filename artifact, not missing content —
  see below.

## Not a defect: the untracked source pages

Four pages persistently appear as untracked:

```text
?? @neural_avb - What Are Looped Transformers?.md
?? Giles Thomas - Why GPT-2 Weights Beat Mine? Part 1.md   (+ Parts 2, 3)
```

Git's index holds these paths with Windows private-use-area characters — `U+F03F` for `?` and
`U+F03A` for `:`, neither being legal in an NTFS filename — while `readdir` on this mount returns
plain ASCII. Both names resolve to the same file, which is why git reports untracked copies without
reporting the tracked originals as deleted.

All four committed blobs are **byte-identical** to what is on disk (1248 / 1201 / 1387 / 1505 B), and
normalizing PUA to ASCII across all 671 tracked files under `knowledge-base/` yields **zero duplicate
paths**. Running `git add` here would commit a second path per file and produce two spellings of every
wikilink target.

**These must stay untracked.** An earlier session recorded them as needing explicit `git add`; that
was wrong and is corrected here.

## Observations, no action taken

- **19 of 91 concept pages cite a single source.** Most are recent and substantive (723-1246w) —
  a new concept legitimately starts from one source. The genuinely thin ones are the *old* single-source
  pages, of which `Model Factory` was the clearest case and is now fixed. The four vault-meta pages
  ([[Persistent Wiki]], [[Index and Log]], [[Ingest Query Lint Loop]], [[Schema-Driven Knowledge Base]])
  are short by nature and describe a stable operating model; they are not candidates for expansion.
- **Source-summary length is bimodal** — median 472w, but short-form captures (ByteByteGo, single
  tweets) sit near 130-160w while essay sources run past 1500w. This tracks source length rather than
  summary quality, so no threshold is worth enforcing.
- **`status: ready`** appears on one page, the social post draft. Intentional.
- **Next single-source pages worth revisiting** if new material lands: `Tabular Foundation Models`
  (194w), `Autonomous Driving Systems` (218w), `Defensive Deception for Open Models` (223w).
